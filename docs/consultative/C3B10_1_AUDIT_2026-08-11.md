# The three defects

## 🔴 F1 (SAFETY) — a currency-symbol **prefix** is not detected, so the price is never checked

```
₫7,500,000        → claims = 0   (MISSED)
7.500.000đ        → claims = 1   ✅
$699 / US$699     → claims = 1   ✅
```

Only `$` is handled as a prefix. `₫` and `VNĐ` are recognised **only as suffixes**. Shopee itself
renders prices as `₫6.490.000`, so this is a form the model sees in evidence and can reproduce.

**Consequence:** an unsupported price written as `₫30,000,000` is invisible to the guard, is
therefore never redacted, and reaches the user. This is a false negative in the one thing the
guard exists to do. Not caught by the 81 tests or by 16/16 mutations, because no test used the
prefix form.

## 🔴 F2 (SAFETY / UX) — the guard can empty the entire reply

```
input  : "Galaxy S24 khoảng 30 triệu."      (the only sentence, unsupported)
guard  : ""                                  (whole clause removed)
filter : if (finalText) controller.enqueue(…)   ← streamEnrichment.ts:505
```

An empty string is falsy, so **nothing is enqueued and the user receives an empty assistant
reply.** Confirmed from two directions: the guard's own output (`""`) and the truthiness check in
the diff. This is the same failure mode this project already shipped once with `maxSteps: 1`.

None of the six fixtures triggers it — they are long replies with several sentences — so the
regression corpus does not cover it.

## 🟠 F3 (QUALITY) — clause removal leaves dangling connectives

```
in : S24 rẻ hơn khoảng 3–5 triệu và phù hợp nếu bạn ưu tiên camera.
out: và phù hợp nếu bạn ưu tiên camera.
§8 expected: S24 phù hợp nếu bạn ưu tiên camera.
```

The output opens with a bare *"và"* ("and") and loses the subject. It invents nothing — the safety
property holds — but it is malformed Vietnamese shown to a user, and it is the exact example §8
specified.

## F4 (finding, not a defect) — the turn-level authority gate

`hasStructuredPrice = records.some(...)` is evaluated **per turn, not per product**. So:

| turn | Bose claim (Bose records have no `price`) |
|---|---|
| mixed: S24 priced + Bose unpriced | **redacted** |
| organic only: Bose unpriced | **preserved** |

The identical claim, with identical (absent) evidence for that product, is treated differently
because of an unrelated product in the same turn. At the per-entity level this does conflate
*evidence unavailable* with *claim disproven* — the distinction §3 exists to protect.

It errs toward removal, so it cannot leak a false price; it is a false-reject risk, not a leak.
Reported for an owner decision rather than classified as a safety defect.

## F5 (correction to my own C3-B.10 report) — the latency figure was not representative

I reported **0.327 ms/call**. That was measured on a fixture with ~3 claims. Latency scales with
**claim count × text length**:

| response size (many claims) | measured |
|---|---|
| 500 chars | 0.633 ms |
| 2,000 chars | 2.965 ms |
| 8,000 chars | 9.057 ms |

Typical replies (~2,300 chars, 2–4 claims) do land near the original 0.327 ms, and even the worst
case is negligible against a 6–13 s turn — but "0.327 ms/call" as a flat claim was wrong and the
"sub-millisecond" acceptance wording is only true for typical claim counts.

## 9. Streaming / client safety

`a:` evidence frames and `0:` prose frames are distinct; the guard operates only on the prose
about to be enqueued, inside `emitReconstructed()`, before the final `controller.enqueue`. A price
appearing in an `a:` frame is internal evidence and is **not** leaked prose — an early version of
my own integration test asserted on the whole stream and would have mis-read exactly that.

## 11. Test-first violation — the remaining gap it caused

The implementation was written before the tests. The 81 tests and 16/16 mutations are real, but
they were written to describe code that already existed, and that is visible in the result:
**F1 and F2 are both behaviours the code never had, so no test asked for them.** A test-first pass
starting from the policy text ("every monetary claim", "remove only the assertion") would plausibly
have produced a `₫`-prefix case and an "output must never be empty" case. This is the concrete cost
of the ordering, not a hypothetical one.
