## 3. What changed in the code

**F1 — prefix currency.** A second extraction pass, run *before* the suffix pass so
`₫7,500,000` is claimed whole rather than leaving a bare number behind:

```ts
const PREFIX_UNIT = '(₫|VNĐ|VND|US\$|\$)'
const PREFIX_RE   = new RegExp(`${PREFIX_UNIT}\s*${NUM}`, 'giu')
```

**F2 + F3 — one mechanism, per the owner's locked policy.** `redactUnsupportedClaims` now:

1. removes the **whole sentence** containing an unsupported amount (this is what kills the
   dangling connective);
2. widens to removing **only the amount and the hedge introducing it** — but *only* when step 1
   would leave no letters at all, so the prose can never become `""`.

Sentence spans are bounded so they can never swallow `[CTA_BUTTONS]`, `[FOLLOWUPS]`,
`[TAPPY_PLAN]` or a URL, and both paths still write nothing: every output character comes from
the input.

## 5. Two bugs found during the fix

* **Mine, introduced by the fix:** the first sentence splitter treated *every* `.` as a boundary,
  so it cut inside `7.99–10.99M` and left `99–10.99M` behind — a brand-new unsupported claim
  created by the redactor itself. **Caught by the C3-B.9 fixtures**, which is precisely why they
  exist. Fixed by requiring whitespace after the terminator; `M21` locks it.
* **Stale mutation anchor** (`M08`), which had been reporting SKIP rather than a pass — the kind
  of inert mutation this project has been bitten by before.

**Honest note on F3.** For a *single-sentence* reply the fallback keeps `rẻ hơn` ("cheaper") after
removing the figure — an unsupported **comparative** without a number. That is outside the money
guard's scope (it governs numeric claims; comparatives belong to the C3-B.5 grounding contract),
and it is the trade-off the owner accepted when choosing "prefer sentence removal, widen only when
it would empty". In multi-sentence replies — the normal case — the whole sentence goes and the
comparative goes with it.

## 9. Remaining risks

1. **The guard is still inert in production** until retrieval returns structured prices. This fix
   changes nothing user-visible today; it makes the guard safe *for when* that lands.
2. **F4 (per-turn authority gate)** from the audit is unchanged — deliberately, it was not in
   scope. A product with no structured price still has its claims redacted when another product in
   the same turn does have one.
3. **Single-sentence fallback can leave an unsupported comparative** (`rẻ hơn`), as described in §6.
4. **Latency** is claim-count driven: ~0.6 ms at 500 chars, ~2.3 ms at 2,000, ~9.1 ms at 8,000 with
   many claims. Negligible against a 6–13 s turn, but not a flat sub-millisecond figure.
5. **Degenerate input** — a reply consisting of nothing but a bare price would still reduce to
   punctuation. No realistic path produces one, and no fixture exhibits it; stated rather than
   hidden.
