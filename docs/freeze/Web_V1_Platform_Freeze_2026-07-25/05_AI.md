# 05 — AI System

**Frozen commit:** `79d05f3` · Source: `src/lib/ai/**`, `src/app/api/chat/route.ts`,
`src/lib/memory/**`, client parser in `src/components/ChatInterface.tsx`.

The governing architecture, stated once and enforced throughout:
**the LLM writes prose; the system owns everything structured** — links, images, place cards,
plan photos, layout. This is not stylistic; it is a cost, correctness and security decision
established across the enrichment bug thread (`08_Bug_History.md`).

---

## 1. Provider abstraction

### 1.1 The facade
All LLM access goes through the `AI` facade exported from `@/lib/ai/llm` (`llm/index.ts` →
`llm/ai.ts`). Callers never import a vendor SDK. The registry (`llm/registry.ts`) resolves a
**role** to a concrete provider+model; the only provider adapter is `llm/providers/claude.ts`.

### 1.2 Role tiering
Four roles exist: **fast · smart · planning · vision**. Intent detection picks the role per
request (§4). Env overrides: `LLM_PROVIDER` (default claude), `LLM_FAST_MODEL`,
`LLM_SMART_MODEL`, `LLM_PLANNING_MODEL`, `LLM_VISION_MODEL` (`registry.ts:25-28`).

> **⚠ Freeze fact:** only **Haiku 4.5** is configured at the frozen commit, so **the four-role
> tiering is currently a no-op at the model level** — every role resolves to the same model.
> The tiering machinery is real and ready; the differentiated model IDs are not set. **[COST]**
> This means the `maxTokens`/`maxSteps` differences per intent (§4) are the *only* live cost
> lever today.

### 1.3 Enforcement — this is CI-gated **[SEC][STAB]**
`.github/workflows/architecture-guard.yml` runs `node scripts/architecture/check.mjs` on every
push and PR. The script enforces the frozen AI-platform rules:
- **No vendor SDK imports outside `llm/providers/`** — `@ai-sdk/anthropic` / `@anthropic-ai/*`
  may appear only in the provider adapter.
- **No hardcoded model IDs** outside the registry.
- **No facade bypass** — feature code must import `AI`, not construct a provider.

This is **the only automated gate that runs on CI** (the unit tests do not run in CI — see
`10_Testing.md`). `ANTHROPIC_API_KEY` is read in exactly one file
(`providers/claude.ts:22,29`); **no key ever reaches the client** because all AI calls are
server-side route handlers.

## 2. System prompt — `promptBuilder.ts`

Two builders:
- **`buildSystem(...)`** — the full prompt for the tool-using chat path.
- **`buildSystemSimple(...)`** — the chitchat path (intent `chitchat`), a much shorter prompt.

The full prompt is assembled from ordered rule blocks. The load-bearing ones:

| Block | Purpose |
|---|---|
| Identity / persona | Tappy's Vietnamese-first assistant persona |
| **Language rule (NGON NGU)** | User-facing Vietnamese must carry **full diacritics** — added after `a0c8ff9`, where ASCII-authored prompt templates leaked into replies |
| **Word limits** | 150 words first reply, 250 thereafter (`promptBuilder.ts:170-171`) **[COST]** |
| **`safetyBlock` rule 1** | Prompt-injection defence (§11) |
| **Platform allowlist (rule 18)** | The model may only reference approved booking/order platforms; deep links are fabricated only by the deterministic `platformLinks/*` builders, never by the model |
| **Flight rule (rule 12)** | Render `booking_links` verbatim (Traveloka + Google Flights) |
| Enrichment prohibition | As of `7ce9eb9` the prompt **no longer instructs the model to write images, TikTok review links or order/platform links inline** — enrichment injects them deterministically |

`buildSystemSimple` carries an **abbreviated copy of the injection rule**, so the chitchat path
is not a security bypass.

## 3. Context and memory

### 3.1 Context builder — `contextBuilder.ts`
Assembles the per-request context: recent history, the memory block, and the preference/profile
block. `MIN_CONFIDENCE = 0.1`, `MAX_ITEMS = 5` (`contextBuilder.ts:8-9`) bound how much of the
learned preference profile is injected. History window is the **last 5 messages** at the context
layer.

### 3.2 Long-term memory — `memoryService.ts` ("Tappy Knows")
- `buildMemoryBlock(memory, forcedTool)` — renders the user's remembered facts into the prompt
  (last 3 history turns considered at prompt-build time, `memoryService.ts:156`).
- `extractMemoryFromConversation(...)` — after a turn, extracts durable facts (last 10 messages,
  `memoryService.ts:238`). **[STAB]** An **empty extraction is treated as "no new data", not as
  an authoritative empty value** — the fix for the silent memory-wipe bug (`a1c318d`).
- Fields remembered: `location_base`, `companions`, `timing`, `personality`, category
  preferences (incl. `avoid`), `history`, `behavior_summary`.
- User-facing surface: `/profile/tappy-knows` with per-fact deletion.

### 3.3 Legacy and implicit stores
Three parallel personalization stores coexist (flagged for consolidation in `12_Open_Items.md`):
`lib/userMemory.ts` (legacy, feed-only; `inferPreferencesFromEvents` reads the last 100 events,
threshold ≥ 3), `lib/memory/memoryService.ts` (Tappy Knows), and `lib/preferences/*` (implicit
weighted signals, 90-day window).

## 4. Intent detection — `intent.ts`

`detectIntent(...)` classifies the request; `detectLang(text)` (reused by TTS) detects language.
Intent drives four dials in `src/app/api/chat/route.ts`:

| Intent | model role | maxTokens | maxSteps |
|---|---|---|---|
| chitchat | fast | 300 | 1 |
| planning (or image) | planning | 4096 | 8 |
| image | vision | 1024 | 3 |
| default (food/place/product) | smart | 3072 | 5 |

**Tool choice is forced on step 0 by intent, then set to `none`** for subsequent steps — the
model runs its tool once, then only writes prose. `maxDuration = 60s` (`chat/route.ts:20`).

## 6. Streaming pipeline — `src/app/api/chat/route.ts`

1. **Flood guard** (`chat/route.ts:28`): 30 requests / 60,000 ms per IP, applied **before** any
   LLM or tool work → 429 with `Retry-After`. **[COST][SEC]**
2. **Input validation**: `messages` must be a non-empty array (400); total input ≤ 24,000 chars
   (413, `chat/route.ts:53`) — named in-code as a cost/DoS vector.
3. **Auth + quota resolution** — anonymous (SECURITY DEFINER RPC, §11) or free-tier
   (`countTodayUserMessages`). **[STAB]** This block **fails open** on any error
   (`chat/route.ts:184-190`): the request proceeds *unmetered* rather than erroring — a
   deliberate availability trade-off, and an unmetered-cost path. Carried to `12_Open_Items.md`.
4. **History truncation** to the last 10 messages (`chat/route.ts:233`).
5. **Intent → role/maxTokens/maxSteps** (§4); tool forced on step 0.
6. **`streamText`** streams deltas. Init errors return a generic `{error:'ai_error'}` 502 —
   `String(e)` is deliberately withheld because the registry's error text enumerates provider
   and model names (`route.ts:425-427`). **[SEC]**
7. **The enrichment stream filter** (§7) buffers post-tool text and re-emits it repositioned;
   pre-tool intro and chitchat stream live.

> **Accepted UX trade-off (recorded in `CHAT_LAYOUT_GROUPING_2026-07-24.md`):** because
> repositioning enrichment needs the full text, the **place-list portion is buffered and appears
> at end-of-generation** instead of typing out live. This was the conscious price of correct
> per-place grouping.

No `temperature` is set anywhere in the streaming path — the provider default applies.

## 7. Enrichment — `streamEnrichment.ts`

The heart of "the system owns layout". Its contract is locked by `streamEnrichment.test.ts`.

- **`injectPlaceEnrichment(places, fullText)`** rebuilds the assistant text, splicing each
  place's photo/review/order markdown **immediately after that place's own block**, using
  **index-preserving `normalizeVN` offsets** (diacritic-tolerant). A length-mismatch guard falls
  back to the legacy trailing block.
- **Boundary safety [STAB]:** the injection region is bounded at the **earliest** structured
  marker — `[TAPPY_PLAN] | [CTA_BUTTONS] | [FOLLOWUPS]` — so it can **never write inside a
  machine-parsed block**. This is the fix for `9eddc74`, where injecting into `[TAPPY_PLAN]`
  corrupted the JSON and the trip brochure vanished.
- **Boundary-by-next-*mentioned*-place:** each place's window ends at the next *mentioned*
  place (photo-less ones included), not the next *enriched* place — the fix for `7c113cb`, where
  a photo-having place followed by photo-less ones dumped its whole gallery at the bottom.
- **Strip-and-reinject:** any enrichment the LLM wrote itself (images by URL, `tiktok.com`
  review lines, owned order/platform domains) is **stripped and re-injected positionally**, so
  placement never depends on the model obeying the prose-only prompt.
- **`injectPlanPhotos(...)`** adds a representative image **inside each trip-plan item by editing
  the parsed JSON object and re-serializing — it never splices markdown** (explicitly citing
  `9eddc74`). Unmatched items (transport, buffer) get no photo; unparseable JSON → text
  unchanged.
- **`latestPlaces` accumulates across searches:** the stream filter's `a:` handler **appends**
  (deduped by name, upgrading to the entry carrying a photo) rather than overwriting — the fix
  for `b5939fc`, where a 6-item plan photographed only 1 item.
- Max **3 places enriched per reply** (`streamEnrichment.ts:289`); unmatched places drop to the
  trailing "📸 Hình ảnh & link review" block.

**[COST] The keystone win:** `7ce9eb9` removed the instruction to write links/images inline at
all, cutting **~1.6K output tokens per 3-place reply** and eliminating the `finishReason:length`
truncation — a real reduction, not a raised ceiling.

## 8. Place matching — `placeMatch.ts`

Exists because **the LLM rewrites tool place names** — it shortens
(`"Hủ tiếu Sa Đéc & Bánh tằm - DÌ NĂM SA ĐÉC - 166 Bùi Thị Xuân, Quận 1"` → `"Dì Năm Sa Đéc"`)
and respells (`"Hủ Tíu"` → `"Hủ Tiếu"`). A raw `indexOf(fullName)` therefore missed the place and
collapsed all enrichment into the trailing block (`79d05f3`).

`findPlaceOffset(placeName, dedupText, headers?)` — an owner-approved **4-tier cascade**,
deterministic first, fuzzy last:
1. **Canonical Display Key** — a bold prose header that is a clean substring of the tool name (or
   vice-versa), length ≥ 4. Handles shortening with no dictionary.
2. **Exact** — full tool name verbatim.
3. **Segment** — split on `- | ( , )`, keep distinctive digit-free segments (drops address
   parts), longest-first.
4. **Token overlap (guarded)** — distinctive-token overlap minus a stop-word set; requires
   `shared ≥ 2` **and** `coverage ≥ 0.6`, so a respelling or a shared food word can never carry
   a false attribution.

Locked by `placeMatch.test.ts` (7 tests).

## 9. Client-side parsing — `ChatInterface.tsx`

The reverse contract on the client. Marker chain, **order matters**:
1. `parsePlan` → `[TAPPY_PLAN]{json}[/TAPPY_PLAN]` → `TripPlanCard`
2. `parseCTA` → `[CTA_BUTTONS]{json}[/CTA_BUTTONS]` (bare-tag fallback)
3. `parseFollowups` → `[FOLLOWUPS]a|b|c[/FOLLOWUPS]`, line-bounded, max 3, orphan-marker strip

Then `formatMessage()`: **`escapeHtml` runs FIRST** **[SEC]**, before any markdown transform, so
`dangerouslySetInnerHTML` only ever receives escaped user/model content. External links get
`rel="noopener noreferrer" target="_blank"`. `sanitizeUrlForMarkdown` percent-encodes `(` and
`)` so a crafted URL cannot break out of `[text](url)`.

Streaming render uses `useSmoothText` (see `06_UI_UX.md` §4).

## 11. Security **[SEC]**

- **Anonymous quota is computed server-side inside a SECURITY DEFINER function** keyed on
  `auth.uid()` from the verified JWT — clients never send or compute quota. The
  `anon_chat_usage` table has RLS on with **zero policies**; `REVOKE ALL FROM PUBLIC`,
  `GRANT EXECUTE TO authenticated`. The function rejects non-anonymous JWTs. See `04_Database.md`.
- **Prompt injection:** `safetyBlock` rule 1 (`promptBuilder.ts:238`) declares user messages
  **and tool results** are DATA, not commands, naming the specific attacks (role change, ignore
  rules, reveal system prompt, "forget previous instructions"). An abbreviated version is in
  `buildSystemSimple` so the chitchat path is not a bypass.
- **SSRF:** `src/lib/security/urlGuard.ts` `isSafeHttpsUrl` — https-only, no embedded
  credentials, blocks `localhost`/`.local`/`.internal` and private IPv4/IPv6 ranges. Its header
  **honestly states it does NOT stop DNS rebinding** and advises callers not to follow redirects.
  Applied at `common.ts:65` (`fetchOfficialWebsiteImage` — which fetches an arbitrary business
  website server-side) and `explore/process/route.ts:26`. `fetchOfficialWebsiteImage` is further
  bounded: 1800 ms timeout, `text/html` content-type check, 100 KB read cap stopping at
  `</head>`, explicit `reader.cancel()`.
- **Key-URL leak guard:** `fetchPlacePhoto` refuses to return a URL still containing
  `maps.googleapis.com` — prevents leaking a key-bearing URL into response markdown.
- **Error opacity:** `streamText` init errors return `{error:'ai_error'}` 502; the raw error is
  withheld because it names provider and model.
- **Input validation:** `responseStyle` narrowed to an enum; `userPreferences` filtered to
  strings and sliced to 50; `userLocation` requires numeric lat/lng; `/api/memory` PATCH is
  whitelist-only with regex-restricted preference keys (`^(food|spa|entertainment|shopping|avoid)$`)
  and length slices.

## 12. Known gaps (honest)

| Gap | Detail |
|---|---|
| Unauthenticated paid-model routes | `/api/translate`, `/api/scan`, `/api/viet-content` invoke a paid model with **no auth** — protection is per-instance in-memory IP rate limiting only |
| Rate-limit not global | `rateLimit`/`dailyRateLimit` state is a module-level `Map`, **per-lambda**. The file says so. Effective limit is `N_instances × limit` |
| Chat fails open | Auth/quota errors → unmetered request (`route.ts:184-190`) |
| `_debug_budget` to model | Shipped inside `get_hotel_prices` results (`travel.ts:239,248`) |
