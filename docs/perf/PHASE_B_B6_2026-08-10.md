# Phase B — B6: memory-extraction cost gate

Measured **2026-08-10**, branch `perf/chat-cost-phase-b`, on top of **B1 + B2 + B4**.
Real Anthropic API; extraction called directly rather than through an
authenticated session, so no test user is written into the production Supabase
auth project.

---

## 1. Baseline — what the gate does today

The shipped gate is one line: `worthExtract = lastText.trim().length > 20`,
combined with `authedUserId`. Measured across 17 representative turns it is wrong
**in both directions**:

| | turns | detail |
|---|---:|---|
| **False positives** — fired, stored nothing | **4** | weather VI, gold VI, news VI, gold EN |
| **False negatives** — skipped real durable information | **3** | `Tôi ăn chay.` (12), `Mình thích cay` (14), `Nhà mình ở Quận 3.` (18) |
| Correct | 10 | |
| **Fires on** | **12 / 17** | |

`Tôi ăn chay.` is the serious one. The system prompt treats dietary constraints
as absolute (*"TUYET DOI KHONG goi y mon an hay quan vi pham dieu do"*), and the
20-character rule meant it never reached memory at all.

Extraction itself is not the problem — measured against the real API:

- **11 / 11** durable turns produced memory
  (`preferences`, `companions`, `budget`, `location_base`, `history`)
- **4 / 6** ephemeral turns produced **nothing at all** — those calls are pure waste
  (the other two produced only a `history` topic such as *"thời tiết Hà Nội"*)

Extraction call cost, measured: **≈83 in / ≈48 out tokens ≈ $0.00032** on a
shortened probe prompt. The shipped prompt adds ~600 tokens of template, so the
real figure is higher — but it is a **`fast`-role call against a small prompt, and
it is not the main cost driver in a turn**.

## 2. Gate design

`src/lib/ai/memoryGate.ts` — `shouldExtractMemory({ text, intent, forcedTool })`,
evaluated in this order:

1. `intent === 'chitchat'` → **skip**
2. **durable signal present → EXTRACT** (checked *before* the category rules, so a
   stated fact can never be masked by an ephemeral-looking question)
3. ephemeral lookup — `forcedTool ∈ {get_weather, get_gold_price, get_news}` **or**
   an ephemeral topic (weather / gold / exchange rate / fuel / news, VI **and** EN)
   → **skip**
4. normalized length < 12 → **skip**
5. **default → EXTRACT**

Two deliberate choices:

- **Biased towards extracting.** A skipped call saves a fraction of a cent; a
  dropped preference is gone permanently. Anything the gate cannot classify
  extracts.
- **Bilingual by construction.** `detectForcedTool`'s gold/weather patterns are
  Vietnamese-only, so relying on it alone would have skipped these for VI users
  while billing EN users for calls that store nothing. The topic list carries both
  languages, so the saving is not VI-only.

This is a **pre-filter, not a memory system** — all semantic work stays in
`extractMemoryFromConversation`. Rule 5 is why: ordinary requests routinely carry
durable signal (`Gợi ý quán ăn ngon ở Quận 1 giá dưới 200k` measurably yields
`location_base` + `budget` + `history`), so they keep extracting.

## 4. Tests

Written first; RED (module absent), then driven green. **47 cases**: SKIP set
(chitchat + ephemeral, VI and EN), EXTRACT set (VI durable, EN durable, ordinary
requests, short location-bearing requests), durable-beats-ephemeral override,
too-short, empty.

**Mutations — 3 applied, 3 RED** (one only after strengthening the guard):

| mutation | result |
|---|---|
| ephemeral check moved *before* the durable-signal check | RED — `Giá vàng hôm nay? Tôi ăn chay nhé` |
| length floor raised back to 21 (the old behaviour) | **SURVIVED at first** — every short EXTRACT case also matched a durable phrase, so the floor was untested. Added four short location-bearing cases with no first-person marker (`Quán ăn Quận 7`, `Cafe ở Đà Nẵng`, `Spa tốt ở Hà Nội`, `Hotels in Da Nang`); re-run → **RED, 4 failures** |
| dietary/allergy terms removed from the signal list | RED — `Giá vàng hôm nay? Tôi ăn chay nhé` |

Suite: **1 126 passed / 0 failed** (excluding the four pre-existing sources).
Architecture guard 8/8.

## 5–8. Before / after

| Metric | before | after |
|---|---:|---:|
| Turns measured (representative set) | 17 | 17 |
| **Memory-extraction calls** | **12** | **11** |
| Change | — | **−8.3 %** |
| **Wrong decisions** | **7** | **0** |
| — false positives (paid, stored nothing) | 4 | 0 |
| — false negatives (durable info lost) | 3 | 0 |
| Extraction input tokens | 12 × ~83 ≈ 996 | 11 × ~83 ≈ 913 |
| Extraction output tokens | 12 × ~48 ≈ 576 | 11 × ~48 ≈ 528 |
| Estimated extraction cost | ≈ $0.0039 | ≈ $0.0036 |
| Total LLM calls (2/turn + extraction) | 46 | 45 |

> **The Phase A estimate of "40–50 % of authenticated turns" was wrong and is
> withdrawn.** Measured, it is **8.3 %** on this set. The reason: place, shopping
> and planning turns — the bulk of real traffic — genuinely *do* carry durable
> location and budget signal, so they must keep extracting. Phase A assumed
> factual lookups dominated; they do not.
>
> **B6 is not primarily a cost optimization.** It removes 4 wasted calls, adds 3
> that were wrongly skipped, and nets out at one call saved. Its real value is
> that memory stopped silently dropping dietary constraints, preferences and home
> districts.

Applied to the 24-turn benchmark scenario set the same way, extraction calls go
**19 → 17 (−10.5 %)** — same order of magnitude. (Those turns are anonymous in the
benchmark, so extraction does not actually run; the figure is the gate decision
applied to that text.)

## 9. Memory-quality verification

| check | result |
|---|---|
| durable turns still reach extraction | **11/11** |
| extraction still yields memory for them | **11/11** — `preferences`, `companions`, `budget`, `location_base`, `history` |
| previously-dropped durable turns now extract | **3/3** (`Tôi ăn chay.`, `Mình thích cay`, `Nhà mình ở Quận 3.`) |
| durable statement inside an ephemeral question | extracts (ordering rule; mutation-tested) |
| ordinary place/budget requests | still extract (rule 5) |

**Accepted trade-off:** weather and gold turns previously produced a `history`
topic (e.g. *"thời tiết Hà Nội"*). Those are no longer recorded. History for a
point-in-time lookup is low value, and the owner's brief lists these categories as
SHOULD SKIP.

## 10. Cross-platform

Backend-only, and the gate sits inside `onFinish` — which runs **after** the
response has finished streaming. Verified by reading the call site: `worthExtract`
guards **only** the `extractMemoryFromConversation` + `updateMemory` block. The
telemetry log, the stream, CTA/follow-up blocks and tool results are all outside
it.

| unaffected | why |
|---|---|
| final streamed response | produced before `onFinish` fires |
| CTA / follow-ups | part of the model's text, already streamed |
| tool results | emitted during generation |
| conversation persistence | client-side `POST /api/conversations`, independent |
| subscription / account | read earlier in the request |
| error handling | the extraction block has its own try/catch; skipping means not entering it |

End-to-end on the running route — all five turns returned real replies:

```
"Hôm nay thời tiết Hà Nội thế nào?"  worthExtract=false  forcedTool=get_weather     447 chars
"Giá vàng hôm nay bao nhiêu?"        worthExtract=false  forcedTool=get_gold_price  485 chars
"Tôi ăn chay."                       worthExtract=true   forcedTool=null            236 chars
"Tôi thích món ăn ít cay."           worthExtract=true   forcedTool=null            186 chars
"Cảm ơn bạn."                        worthExtract=false  forcedTool=null            109 chars
```

**No client change made or required.**

## 11. Bilingual

| | VI | EN |
|---|---|---|
| ephemeral skipped | weather, gold, news, exchange rate | weather, gold price, news headlines, exchange rate |
| durable extracted | 12 cases | 7 cases |

The topic list is bilingual specifically so the gate is not language-dependent.
Had it relied on `detectForcedTool` alone (Vietnamese-only patterns), EN users
would have kept paying for calls that store nothing — the saving, not the capture,
would have been VI-only. Either asymmetry is a defect; neither is present.

## 12. Remaining risks

1. **The signal list is a heuristic.** A durable fact phrased unusually *inside an
   ephemeral question* would be skipped. Narrow by construction: outside ephemeral
   turns the default is extract, so a miss costs nothing there. Widening the list
   is cheap if production shows a gap.
2. **`history` for weather/gold lookups is no longer recorded** — accepted, §9.
3. **Authenticated end-to-end untested.** Extraction was measured by direct
   invocation; wiring the gate was verified through the live route via the
   `worthExtract` telemetry field. Exercising a real authenticated turn would mean
   writing a user into production auth, which was not done.
4. **The saving is small.** If memory-extraction cost matters more than this,
   the lever is the ~600-token prompt template inside
   `extractMemoryFromConversation`, not the gate. Out of B6's scope.
