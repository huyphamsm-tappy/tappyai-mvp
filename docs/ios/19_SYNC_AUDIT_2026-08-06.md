No code or doc changes applied yet — this report is for owner review before any implementation.**

## 2. Outdated / incorrect docs and models (drift against current truth)

| # | Item | Evidence | Severity |
|---|---|---|---|
| 1 | **`docs/ios/04_API_CONTRACT.md` wrongly documents `GET`/`PUT /api/reviews/[id]`** | Current route only exports `DELETE`/`PATCH` — no `GET` exists (405). Android hit this live ("notification → review detail no longer dead-ends", `1a27da7`) and had to work around it via cache repopulation since there's no fetch-by-id route. | **High** — a documentation defect that will reproduce an already-discovered, already-fixed-elsewhere bug the moment iOS builds a cold-entry review-detail path (push notification / deep link / share link). |
| 2 | **iOS Privacy Policy content is stale boilerplate** | `StaticPageView.swift`'s `PrivacyPolicyView` names no third parties, doesn't disclose booking/location/personalization data flows, and lists contact `privacy@tappyai.vn`. Blob), OpenStreetMap, Stripe, confirms PostHog is NOT used, and uses `support@tappyai.com`. | **High** — App Store review commonly cross-checks in-app policy text against what's actually disclosed; this is the kind of mismatch that gets an app rejected or flagged. |
| 3 | **`docs/ios/02_FEATURE_INVENTORY.md` + `09_IOS_ARCHITECTURE_BLUEPRINT.md` still spec Games/SuperTux** | Web removed SuperTux from V1 entirely (`7744733` — Blob-quota driven, V1 scope redefined to "AI Chat, Food, Travel, Explore, Reviews, Social"). | 4 | **`SuggestedPrompt` model missing `textEn`** | Backend returns `{text, textEn, category, emoji}`; iOS's `HomeModels.swift` only decodes `text/category/emoji` — Swift silently drops the unknown key. `HomeSectionViews.swift` also hardcodes the VN section header regardless of app language — the same locale-vs-system-language bug Android just fixed (`4255459`), except iOS doesn't even have the EN string wired. | Medium — invisible today (VN-only usage), will break the moment iOS ships an EN locale. |

| 6 | **`docs/ios/04_API_CONTRACT.md` missing Scam Shield + new config flags** | No mention of the 3 new routes, nor `/api/config`'s new `flags.showScamShield` / `scamShield: {dailyLimitAuth, dailyLimitAnon}` block. | Medium — additive gap, not breaking, but doc is incomplete. |

## 3. Business-logic differences

- **Astrology/Fortune Nạp Âm engine — GOOD NEWS, no open bug.** Web's fix (`4afeddf`, correcting the buggy last-digit-of-year heuristic to a real 30-entry Nạp Âm table) was **co-committed to iOS in the same commit**. `CanChiData.swift` already has the corrected `CanChiEngine`/`NapAmEntry` structure, and `CanChiDataTests.swift` has a named regression test for the exact 1985 case Web's fix targeted. Only gap: still unverified by an actual Xcode compile/test run (no Mac in this environment) — recommend closing this the moment a Mac is available, but it is not a logic gap.
- **Deals categoryKey vs. localized category** (see §1.4) — a real business-rule split iOS needs to carry over once Deals is built, or category-color styling breaks on a language switch exactly as it did on Android before the fix.
- **Suggested-for-you language sourcing** (see §2.4) — must follow app language (`@AppStorage` locale), not system locale, matching Android's corrected behavior.
- **Guest-count wording inconsistency inside iOS itself** — `ServiceDetailView.swift` uses "người" while `BookingFormView.swift` uses "khách" for the same concept. Pre-existing (not caused by this audit window), same axis Android/Web's i18n sprint is currently resolving. Low priority; fold in whenever iOS's own i18n pass (F13) happens.

## 4. Security differences

**Nothing new found this cycle.** Confirmed explicitly (not just absence of evidence):
- **Controller V2 (admin/backoffice RBAC) has zero impact on iOS.** It is still in design/audit stage — its own docs state no code, migration, or branch has changed. Its pre-existing predecessor (Phase 0 `admin_roles`/`ADMIN_IDS`) is fully contained to `/admin*` server routes with no leakage into any consumer path, table, or shared middleware. iOS never touches the Next.js browser-cookie middleware at all (it talks to Supabase/API routes directly via bearer JWT), so even a future Controller V2 middleware change would be architecturally invisible to iOS. Re-check once Controller V2's Phase 1 (Owner/permission model) actually merges.
- Next.js CVE-2025-29927 patch (14.2.5→14.2.35) is still **unapplied** on Web (recommendation only, not yet done) — irrelevant to iOS regardless, since it's a server-framework/middleware-bypass fix with no client contract change.
- No new auth/session/entitlement contract changes landed since the last iOS sync (Zalo's `platform=android` addition is Android-scheme-specific and doesn't touch iOS's existing `tappyai://auth/callback` flow).

## 5. Technical debt

- **Deals tab is wired into iOS navigation but shows a placeholder.** `AppTab.swift`/`AppRouter` already has a real `.deals` case with icon/route, but renders `PlaceholderTabView` — code-partial vs. doc-complete drift, distinct from the "not started" items in §1.
- **Notifications module is a single flat file** (push-registration only) — needs a full feature buildout (model, service, UI) once ADR-014's contract is adopted.
- **Memory hygiene:** the standing project memory claim of "228 iOS Swift files, feature-complete" was a misread of `git show --stat 27ac2f2`'s total diffstat (228 changed files across the *whole* commit, including `docs/ios/*.md` and several Backend/Web files) rather than an iOS Swift file count. The real, current count is **166 Swift files** (158 app + 7 tests + 1 UI test). No files were deleted or consolidated — this is a correction to the record, not a regression. Memory will be updated to reflect this.

## 6. Required migrations

**None.** No `supabase/migrations/` drift was found since `d57f5ef` — Scam Shield in particular has **no dedicated DB tables** despite an earlier architecture memory implying `scam_shield_checks`/`scam_shield_official_directory`/`scam_shield_blocklist` tables; it's entirely code/config-driven (hardcoded directory seed, live-fetched external blocklist, Redis/in-memory cache). `docs/ios/05_DATABASE_CONTRACT.md` needs no changes. If iOS eventually builds any of the §1 missing features, none of them require new migrations beyond what Backend already ships — they only require new iOS-side network/model code against existing endpoints.

## 7. Explicitly ruled out / not-applicable

- `/startup` marketing landing page — public, unauthenticated, bilingual; no bearing on the authenticated iOS app.
- Web home-background visual asset changes (V2→V5) — desktop/tablet-only per existing memory; not iOS-relevant.
- Zalo `platform=android` OAuth addition — Android-scheme-specific, doesn't change iOS's existing flow.
- SuperTux removal itself — iOS never had the feature built, so removal is a **docs-only** correction (see §2.3), not a code gap.
- Account-settings i18n sprint (Web/Android, uncommitted, awaiting owner UAT) — architecturally independent of iOS's own future String-Catalogs work (F13); only a narrow copy-parity note carries over (`"Chưa cập nhật"`→`"—"`, `"người"`→`"khách"`) for whenever iOS's Account/Bookings screens get their own i18n pass.
